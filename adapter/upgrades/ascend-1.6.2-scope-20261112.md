# Ascend 1.6.2 升级闭环范围

2026-11-12，用户要求先完成闭环，再自行合并提交及删除临时分支。针对旧门禁将全部 45 项列为必测的问题，
用户明确选择：**“按已确认的暂缓范围闭环，其余功能必须通过”**。

本记录对应 [新计划](targets/dynamo-1.6.2-ascend-scoped.yaml)。不修改旧会话的 lock、analysis、失败日志或已封存候选包。
源码和厂商版本仍为原候选 `1aabe435ad`、Dynamo 1.6.2、vLLM-Ascend 0.30.0；范围重冻结不是一个新的实测结果。

| 暂缓功能 | 边界 |
| --- | --- |
| M06-F05 | G4 远端缓存；本地 G2/G3、独立 KVBM、多卡及 replicated 仍须验收 |
| M07-F01 | 华为 GMS/VMM 共享服务；不能用不支持错误冒充正向功能通过 |
| M07-F02 | 完整图像/视频模型链路；已有本地媒体单元检查仍可作为有限材料 |
| M07-F03 | 完整 VL 路径中的独立编码器传输；保留既有实现，不宣称已实测 |
| M07-F04 | 完整 Omni 阶段 hidden-state 通道及其生命周期 |
| M08-F05 | 厂商 DRA，等待独立的 Kubernetes ≥1.34 测试环境 |
| M09-F05 | 功耗写入/恢复控制；M09-F01 只读观测仍须验收 |

其余 38 项均为 required，不能把未完成的 case 改为 optional，也不能以“已有部分材料”自动通过。
原生引擎已复现的数值不确定性、未达到的负载延迟目标以及 Hybrid 退出异常须保留独立记录。
SLA 分析功能的验收包括如实识别不达标，不意味着要求所有负载都达到生产 SLA。

闭环必须包含：剩余源码审查、上游语义审查、带功能编号的现场验收、配对比较、七步离线交付审计和可执行回退方案。
本范围确认没有授权跳过这些步骤，也没有授权合并 heyi 或删除临时分支。
